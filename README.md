# 四渡赤水 · 三维真实地形动画

1935 年中央红军"四渡赤水"的三维沙盘推演演示。以真实经纬度定位、真实卫星高程地形，
在 WebGL 中重现遵义会议前后的黔北、川南、滇东北战场。

![技术栈](https://img.shields.io/badge/Three.js-r147-blue) ![离线可用](https://img.shields.io/badge/offline-single--file-green)

## 快速开始

直接双击 `四渡赤水3D.html` 即可在浏览器中打开（无需服务器、无需联网构建）。

若希望加载真实 DEM 高程，需要通过 HTTP 访问（`file://` 协议下浏览器会拦截跨域瓦片请求）：

```bash
python -m http.server 8765
# 打开 http://127.0.0.1:8765/四渡赤水3D.html
```

在线时自动加载 AWS Terrarium 高程瓦片（zoom 9）；离线时秒级回退到程序化示意地形。

## 特性

### 地理真实
- 全部城市、渡口、山口按**真实经纬度**定位（遵义 106.93°E/27.73°N、赤水河、乌江、金沙江皎平渡等）
- 地形来自 **AWS Terrarium SRTM 高程瓦片**，山体纵向夸张 ×2.2 增强立体感
- 河流按**实际河宽**渲染为水面（长江 4.8km、金沙江 3.2km、乌江 2.4km、赤水河 1.7km）
- 窗口边界外延展地形，无黑边

### 兵力具象化
兵力不用数字表达，而是画成**小兵方阵**：

| 表示 | 含义 |
|---|---|
| 1 个小兵 | ≈ 5 千人 |
| 红军 | 红色小兵 + 红色圆环底座 + 五角星红旗 |
| 国民党军 | 白色小兵 + 白色圆环底座 + 蓝白色军旗 |

方阵尺寸随镜头距离自动补偿，上帝视角与跟随视角下都清晰可辨；规模差异一眼可见
（薛岳部 8 万 = 32 兵，黔军 1.2 万 = 5 兵）。

### 战斗动画
三场战役有完整的交火演出：**双方弧形阵线展开 → 曳光弹往复飞 → 爆炸火焰与烟柱 →
红军推进冲锋 → 防线崩溃士兵倒地**。战斗触发时镜头自动推近战场（正北俯视，方位不变），
战场附近部队标签自动淡出以免遮挡，战斗期间章节推进冻结，保证过程完整演绎。

### 镜头
- **上帝视角**：正北朝上俯视，每章聚焦各自战场，章节间纯平移+缩放滑窗
- **跟随视角**：紧跟红军主力推进，俯仰与高度平滑过渡
- **自由视角**：可自行拖拽旋转
- 全片**无自动旋转**：终幕画面完全静止，镜头方向任何时刻恒定

### 史实
兵力数字按史载约数配置，各章事件、渡口顺序、敌军番号均按史料编排，并经复核校正：

| 项目 | 本片采用 | 说明 |
|---|---|---|
| 遵义会议时红军 | 约 3.7 万 | 官方通报数；各档案统计约 3.5—3.7 万 |
| 扎西整编后 | 3 万余人 | 缩编为 16 个团，扩红三千余 |
| 渡金沙江时 | 3 万余人 | 官方口径"3 万余人" |
| 国民党围剿总兵力 | 约 40 万 | **全国范围总投入**（含长江南岸封锁部队与地方团练），黔北一线仅其中一部 |
| 遵义战役战果 | 歼灭和击溃敌军 2 师又 8 团 | 官方原文含"击溃"，非单纯"歼敌"；俘敌约 3000 人 |

已按史料校正的关键点：

- **土城·青杠坡战斗**（1.28—29）：青杠坡是土城战斗的主要战场（位于土城以东约 3 公里）；因对川军入黔兵力估计不足，**攻击未果、红军主动转移**，非"战况胶着"
- **娄山关战斗**（2.25—26）：长征以来**最大的一次胜利**，打开遵义门户
- **鲁班场战斗**（3.15）：一次未能奏效的攻坚，红军本身未受重创（与青杠坡性质不同）
- **皎平渡坐标**：102.68°E / 26.52°N，与会理隔江相望（早期版本偏西南约 30 公里）
- **追兵"止步"方位**：必须画在渡点以北（未过江），早期版本误画在渡点以南
- **鸭池河渡口**：贵阳正南 106.74°E / 26.52°N（早期版本偏西约 40 公里）
- **南渡乌江渡口**：东移至 106.66°E / 27.42°N 一带
- **巧渡金沙江**（5.3—9）：6 只木船、7 天 7 夜，**长征中唯一一次无战斗的渡江**
- **会理会议**（5.12）：决定立即强渡大渡河
- **四渡赤水全程**为"**两个多月**"、"十倍于己的敌军"（非"3 个多月""数十倍"）
- **撤离遵义是向西**，非"北上"
- **扎西会议**为"传达遵义会议决议、讨论行动方针"，非"通过决议"
- **三人军事指挥小组**正式组建一般记为 3 月 12 日军委命令
- **佯攻对象是贵阳城**，非息烽
- "打得赢就打，打不赢就走"为**后人对毛泽东军事原则的概括表述**，非 1935 年 1 月原话
- 蒙哥马利轶事标注为"**据纪实回忆**"

地名沿革加注：打鼓新场（时属黔西县，今金沙县）、鲁班场 / 枫香坝 / 猴场（时属遵义县，今播州区）、
郎滩与赤水城（1935 年属四川）、大定（时属大定县，今大方县）。

## 目录结构

```
四渡赤水3D.html      三维演示主文件（单文件，含全部逻辑）
四渡赤水.html        二维 SVG 轻量版
libs/
  three.min.js       Three.js r147 (UMD, 本地引入以支持 file:// 直接打开)
  OrbitControls.js
tools/
  verify.js          无头浏览器验证脚本（抓帧 + 错误检测）
  record.js          录制脚本（MediaRecorder → WebM → MP4）
```

## 开发工具

```bash
npm install                      # 安装 puppeteer-core
node tools/verify.js --shots=out --chapter=1 --frames=12
node tools/record.js --out=四渡赤水3D.mp4 --seconds=122
```

`record.js` 用**虚拟时钟**逐帧渲染（页面内 `window.__offline` 接口），成片帧率与
动画流畅度不受本机 GPU 性能影响——即使在纯软件渲染（SwiftShader）的机器上，
也能输出标准 30fps 的流畅视频。

## 发布

```bash
# 推送到 GitHub（需要 Personal Access Token：经典令牌勾 repo；细粒度令牌需 Contents: Read and write）
GITHUB_TOKEN=ghp_xxx ./tools/publish-github.sh --check   # 先只校验令牌，不推送
GITHUB_TOKEN=ghp_xxx ./tools/publish-github.sh           # 校验通过后推送（仓库不存在会自动创建）
GITHUB_REPO=hovercode2026/sidu-chishui                   # 可覆盖默认仓库名

# 投稿到 B 站（需要登录 Cookie：SESSDATA 与 bili_jct）
node tools/publish-bilibili.js   --cookie="SESSDATA=xxx; bili_jct=yyy"   --file=四渡赤水3D.mp4   --title="四渡赤水 · 三维真实地形推演"
```

Cookie 与 Token 等同于账号凭据，请勿提交进仓库或分享给他人。
`publish-github.sh` 与 `publish-bilibili.js` 已随仓库提供，但需要你自己的凭据才能执行。

注意区分密钥类型：GitHub 令牌以 `ghp_` / `github_pat_` 开头；`sk-` 开头的是模型平台
（OpenAI、Z.AI 等）的 API Key，无法用于 GitHub。`publish-github.sh` 会在联网前先做前缀
预检，并把「令牌无效（401）」与「权限不足（403）」分开报错。推送时令牌只用于当次命令，
不会写入 `.git/config`，避免明文落盘。

`verify.js` 用独立的无头 Chrome 打开页面、跳转到指定章节并连续抓帧，同时输出
页面运行时错误——比在应用内浏览器里调试可靠（应用内标签页被宿主冻结时
requestAnimationFrame 会停摆）。
